# Mod authoring rules

Rules for hand-authored files of the main mod (`mod/Prosper or Perish (Population Growth & Food Rework)`, called M
below): map modes and their icons, farmed goods output modifiers, the Europedia (game concepts and their GUI). They
used to ship inside the mod as `.cursorrules`, `.cursor/rules/*.mdc`,
`in_game/gfx/map/map_modes/MAP_MODE_ICONS.md` and `main_menu/common/game_concepts/Ingame_Documentation_Rules.md`;
moved here 2026-10-24 so the mod folder holds game files only.

## Map modes and their icons

A map mode has three parts that must agree, all keyed by the **map mode id** (the block key in
`M/in_game/gfx/map/map_modes/*.txt`, e.g. `pp_rgo_level`):

1. **Definition** in `M/in_game/gfx/map/map_modes/`: block key = id, `legend_key` descs as needed.
2. **Localization** (e.g. `pp_building_adjustments_l_english.yml`): `mapmode_<id>_name` (picker name),
   `MAPMODE_<ID>` (legend description, id in upper case), tooltip keys such as `MAPMODE_<ID>_TT_LAND`.
3. **Icon** `M/main_menu/gfx/interface/icons/map_modes/<id>.dds`. The basename must be the id exactly (case
   sensitive). Map mode icons live only under `main_menu`, never under `in_game/gfx/interface/icons/map_modes/`
   (the geography sync skips that folder of the World Builder export).

The game concept of the map mode (`M/main_menu/common/game_concepts/*_map_mode.txt`) uses
`texture = "map_modes/<id>"` (path under `gfx/interface/icons/`, no `.dds`). Reuse vanilla art by **copying** the
vanilla `.dds` to `<id>.dds` in the mod; never point a concept or map mode at a mismatched filename (e.g. map mode
`pp_rgo_level` uses `pp_rgo_level.dds`, not `raw_material.dds`). Exception: `pp_building_levels`'s concept still uses
`map_modes/building_based`; leave it unless the DDS is renamed to match.

Icons:

- DDS with mip maps, dimensions divisible by 4 (BC3/DXT5 is safe).
- `pp_local_<good>_output_modifier`: a copy of the vanilla trade-good icon
  `game/main_menu/gfx/interface/icons/trade_goods/icon_goods_<good>.dds` saved as
  `pp_local_<good>_output_modifier.dds` (one icon per good, never one generic texture for the set).
- Other ids without own art: copy one vanilla `game/main_menu/gfx/interface/icons/map_modes/*.dds` as a placeholder
  for that id only; never bulk-replace working icons.
- Some icons are drawn by tools (e.g. `tools/build_navigable_rivers_icon.py`, `tools/build_arable_land_icons.py`).

Geography map modes: `index` must be 0-3 (vanilla's sub-tabs; unique indices 4+ do not show in the Geography picker).
PP's geography map modes use `index = 2`.

Troubleshooting: a blank picker slot means the DDS is missing or misnamed; a raw key in the picker means
`mapmode_<id>_name` / `MAPMODE_<ID>` is missing; an icon that does not load usually lacks mip maps or has a size not
divisible by 4.

## Farmed goods and local output modifier map modes

Vanilla farmed goods (`method = farming` in `game/in_game/common/goods`, EU5 1.4): beeswax, camels, chili, cloves,
cocoa, coffee, cotton, dyes, elephants, fiber_crops, fruit, horses, incense, legumes, livestock, maize, millet,
olives, pepper, potato, rice, saffron, silk, sugar, tea, tobacco, wheat, wine, wool. Their output modifiers are
`local_<good>_output_modifier` / `global_<good>_output_modifier`; a goods output modifier applies to every source of
the good (RGO levels and every building producing it). Victuals are separate.

The local output modifier map modes (`M/in_game/gfx/map/map_modes/pp_local_output_modifier_map_modes.txt`, one
`pp_local_<good>_output_modifier` per good, all `index = 2`) are generated by
`scripts/generate_raw_material_local_map_modes.py` and cover every raw material (fish, wild_game and fur included);
`tools/generate_pp_goods_output_map_modes.py` writes `pp_goods_output_map_modes_generated.txt`. Edit the generators,
not the files.

## Buttons that change the game, and observers

A GUI button changes the game only through a game command (a scripted GUI's `Execute`, every vanilla action). The
game drops every game command an observer sends, without an error (verified 2026-10-24: the welcome situation's
dismiss button closed the panel and left the situation running). A button an observer needs gets an observer twin
(`visible = "[IsPlayerObserver]"`, the player's button `visible = "[Not(IsPlayerObserver)]"`, the box
`ignoreinvisible = yes`) that runs the effect through the console:
`onclick = "[ExecuteConsoleCommand('effect <effect>')]"`. The console's effect runs at once on this machine only, so
never use it for players (not synced in multiplayer; blocked in multiplayer and ironman). Example:
`M/in_game/gui/panels/situation/pp_mod_welcome_situation.gui`.

## Europedia (in-game documentation)

GUI: `M/in_game/gui/encyclopedia_lateralview.gui` (filter buttons and cards), card types in
`M/in_game/gui/shared/pp_europedia_style.gui`; text usually in
`M/main_menu/localization/english/pp_europedia_l_english.yml`.

### Text

- No numbers in the text at all (Jan, 2026-10-09). A number the player needs sits behind a blue link: a concept
  (`[concept|e]`), a modifier (`[ShowModifier('key')]`, its tooltip lists the live effects), a good, building or pop
  type (`[ShowGoodsName('x')|e]`, `[ShowPopTypeName('x')]`). Dates and structure ("each September") are fine.
- Where a linked modifier or concept tooltip already shows the effects (e.g. food storage), do not restate them in
  the prose: explain what the player should understand and where to inspect it.

### Card style (2026-10-09; first card: Variable Harvests)

A card is the usual header tab, then:

1. `pp_eu_banner` - an edge-to-edge picture, 2900 x 500 DDS shown at 1450 x 250. Every banner is a painting of the
   page's topic in the style of the game's loading screens: people doing the thing the page explains, each card its
   own culture and scene (Jan, 2026-10-10: no stitched landscapes; a landscape says nothing about labor). The
   paintings are in `assets/europedia_paintings/` (its README has the brief they were painted from);
   `tools/build_europedia_banners.py` cuts each card's strip (start row set per painting so faces stay in frame) and
   writes the DDS. Override `blockoverride "banner_texture"` with the card's banner.
2. `pp_eu_lead` - one short paragraph in the flavour type: what the mechanic is, in plain words. It is also the
   concept's own tooltip text, so it must read well alone. It is the first text of the card (the web export starts
   there).
3. Optional live line (`visible = "[GetPlayer.IsValid]"`): the mechanic in the player's own game, e.g. the capital's
   harvest medallion. The web export leaves texts that read `GetPlayer` out.
4. Sections: `pp_eu_section` heading (icon + gold title + fading rule), then any of
   - `pp_eu_text` body text;
   - a flow: an hbox (`margin = { 40 0 } spacing = 8`) of up to four `pp_eu_step` with `pp_eu_arrow` between;
   - a scale: an hbox (`spacing = 10`) of up to seven `pp_eu_scale_step`, worst to best, each a medallion and a
     concept link whose tooltip holds the details;
   - goods rows: `pp_eu_goods_row` with a two-line label (`#T name#!\nverdict`) and `pp_eu_item`s (ten to a line; a
     longer row wraps into a vbox of hbox lines; alpha 0.55 on the icon for goods the mechanic leaves alone);
   - a comparison: an hbox (`margin = { 40 0 }`) of two `pp_eu_panel` (items, title, text) with a `pp_eu_sign`
     ("or", "+") or a two-way arrow between them, e.g. store running low vs store full;
   - an equation: `pp_eu_step`s with `pp_eu_sign` "–" and "=" between, e.g. grows – eats = surplus;
   - a list: a vbox (`margin = { 40 0 } spacing = 8`) of `pp_eu_entry` (up to three items) or `pp_eu_entry_wide`
     (four), each a fixed icon column (a small input -> building -> output flow of `pp_eu_item` and
     `pp_eu_item_arrow`, or a row of buildings) next to a title and text.

   **Every icon carries a hoverable game link** (Jan, 2026-10-10: the blue or golden text players know they can
   hover, not an icon with a plain tooltip): a `pp_eu_item` shows its link under the icon (`item_link`), a
   `pp_eu_step` under its icon (`step_link` with a `pp_eu_link`), a scale step in its label. Link the real thing:
   `[ShowGoodsName('x')|e]`, `[ShowBuildingTypeName('x')|e]`, `[ShowPopTypeName('x')]`, the terrain names
   (`ShowTopographyName`, `ShowVegetationName`, `ShowClimateName`), `[ShowModifier('x')]` for a state the game
   applies as a modifier, else a concept. Only the header, banner, section headings, arrows and the live line stand
   without one.
5. Section order that reads well: what happens (flow) -> how strong (scale) -> what it touches -> where to see it in
   game. Keep a card on its own mechanic; neighbouring mechanics get a link in the text, not a section of their own
   (Jan dropped the harvest card's "Where It Leads" flow, 2026-10-09).
6. Cards need not look alike (Jan, 2026-10-10): banner, lead and section headings stay, the rest is whatever explains
   the mechanic best (Food: comparisons; Food Production: an equation and a building list). Concise wins.

Use the mod's own visual language where one exists (harvest medallions = the location view's harvest chip frames).
`tests/test_europedia_style.py` checks textures, keys, links, data functions, that every icon carries a link, that
banners differ and that the text has no numbers; add a new card to its `CARDS` when it adopts the style.

### Card order

Keep the GUI's filter buttons and cards in this order (more may be added):

1. All
2. Overview
3. Food (was Food in EU5)
4. Food Production
5. Food Consumption
6. New Trade Goods
7. Logistics (Market Access) (was Building Limits)
8. Navigable Rivers
9. Rural Capacities (was Building Capacity)
10. Labor
11. Variable Harvests
12. Arable Land (was Population Capacity)
13. Population Growth
14. Other Changes

The Update 0.9 changelog card and the Other Changes cards Cheap Food, Expensive Food (the market food price, switched
off) and Province Current Food Storage (now in Province Food Growth from Storage) were removed 2026-10-24, the Getting
Started and F.A.Q. cards the same day (out of date).
